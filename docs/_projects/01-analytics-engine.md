## Overview

This project demonstrates building a production-grade real-time analytics system that ingests and processes customer data from multiple sources (near-real time and batch).

## Key Features

- **Fault-tolerant ingestion** with Kafka and partition-aware producers
- **Stateful stream processing** using Flink and its checkpoint model
- **Complex event correlation** across multiple data streams

## Architecture Highlights

The system consists of:

1. **Data production layer** - File and events (over IBM MQ) are generated by Mainframe
2. **Data Migration** - Events are moved to Apache Kafka though Confluent connectors, instead batch files are saved over shared NAS.
3. **Data Ingestion Layer** - According to functionality, every ingestion job merges events and batches into a single flow.
4. **Stream Processing** - Another flink job saves the preceeding single flow into MongoDB collection.  
5. **Query API** - Low-latency REST endpoints for application usage

## Lessons Learned

- Monitoring and alerting are critical in streaming systems
- Exactly-once semantics require careful state management
- Backpressure handling prevents cascading failures
